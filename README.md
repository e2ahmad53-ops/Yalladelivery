# Yalla Delivery | يلا دليفري

نسخة أولية جديدة (MVP) مبنية من المواصفات المتاحة. ليست استرجاعاً لكود المحادثة السابقة، وليست نسخة جاهزة للنشر أو تشغيل أرصدة حقيقية.

## المكونات

- `backend/`: API بلغة Python 3.12 وقاعدة SQLite، بلا حزم Python إضافية.
- `apps/admin/`: لوحة إدارة عربية للطلبات والحسابات والكباتن والمحافظ والمحادثات.
- `apps/mobile/`: مصدر React Native / Expo مشترك ينتج تطبيق متجر وتطبيق كابتن، بأسماء ومعرّفات منفصلة لأندرويد وآيفون.
- `backend/tests/`: فحوصات منطق العمل والتزامن والصلاحيات وHTTP.

## تشغيل تجربة محلية

من جذر المشروع:

```bash
python3 backend/setup.py --phone YOUR_ADMIN_PHONE --demo
python3 backend/server.py
```

أدخل كلمة مرور جديدة عند الطلب؛ لا توجد كلمة مرور ثابتة بالكود. افتح `http://127.0.0.1:8000` لدخول لوحة الإدارة. الخيار `--demo` ينشئ متجراً وكابتنين في منطقة السابع فقط للاختبار، بنفس كلمة المرور التي أدخلتها:

| الحساب | اسم الدخول |
|---|---|
| المدير | الرقم الذي مررته في `--phone` |
| المتجر التجريبي | `demo-store` |
| الكابتن الأول | `demo-captain-1` |
| الكابتن الثاني | `demo-captain-2` |

لتشغيل حقيقي لاحقاً، أنشئ قاعدة جديدة دون `--demo`. بيانات التجربة لا تُستخدم لأرصدة حقيقية. يمكن تغيير مسار القاعدة بواسطة `YALLA_DB`.

## تطبيق المتجر والكابتن

في `apps/mobile/`:

```bash
npm ci
cp .env.example .env
```

اضبط `EXPO_PUBLIC_API_URL` على عنوان الخادم الذي يصل إليه الهاتف؛ `localhost` على الهاتف يشير إلى الهاتف نفسه. لتجربة شبكة محلية موثوقة شغّل الخادم بـ `python3 backend/server.py --host 0.0.0.0`، ثم ضع IP جهازك. للإصدارات المبنية استخدم HTTPS وشهادة صحيحة؛ السماح بـ HTTP على الجهاز يختلف حسب نظام التشغيل وبناء التطبيق.

```bash
npm run start:store
# أو بعد إيقاف الخادم السابق:
npm run start:captain
```

يستخدم المشروع Expo SDK 55، React Native 0.83.10 وReact 19.2؛ ضُبطت نسخ الحزم وفق قائمة التوافق المرفقة بحزمة Expo المثبتة. راجع توثيق خط SDK: https://expo.dev/blog/upgrading-to-sdk-55 . قد تتطلب تجربة SDK 55 بناء تطوير مناسباً إذا لم تدعمه نسخة Expo Go المثبتة. راجع https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/ .

ملف `eas.json` يعرّف ملفات بناء منفصلة للمتجر والكابتن. لم يُنفذ بناء APK/IPA أو نشر المتاجر. يلزم ربط مشروع EAS، ضبط عنوان API لكل ملف بناء، ومعرّفات نهائية وشهادات Apple/Android قبل التوزيع. اعتمد البناء المنفصل لكل نوع حساب، لا تبديل الدور داخل تطبيق منشور.

## الوظائف الموجودة

- إنشاء طلب من المتجر، وملاحظات، وموعد مجدول. الطلب المجدول يظهر للكباتن عند موعده؛ لا يوجد إشعار خلفية بالموعد بعد.
- عرض الطلب للكباتن في منطقته، وأول قبول ناجح يحصل عليه؛ قبول ذري داخل معاملة قاعدة بيانات.
- حتى 3 طلبات نشطة لكل كابتن، بشرط تطابق `route_group`. المجموعة تُدخل يدوياً؛ **ليست حساباً آلياً للمسار أو ضماناً لتقارب العناوين**.
- إسناد الطلب وتحويله من كابتن لكابتن من الإدارة قبل الاستلام من المتجر؛ يُرفض التحويل بعد الاستلام.
- حساب عمولة الشركة 15% من سعر التوصيل فقط، وحجزها عند القبول ثم خصمها مرة واحدة عند التسليم. الإلغاء الإداري يحرر الحجز.
- محفظة كابتن: الرصيد الإجمالي والمحجوز والمتاح، سجل الحركات، شحن إداري، وتحويل إلى كابتن آخر بمفتاح يمنع تكرار الخصم. لا يوجد دفع بنكي أو بوابة دفع أو سحب نقدي آلي.
- دعم داخلي يصل للإدارة وشات مرتبط بالطلب بين المتجر والكابتن؛ بعد التحويل لا يصل الكابتن القديم للمحادثة، وبعد إغلاق الطلب تصبح للقراءة فقط.
- موقع الكابتن أثناء استخدام التطبيق بعد إذن الموقع؛ المتجر يصل إلى موقع كابتنه أثناء الطلب النشط فقط. لوحة الإدارة تعرض آخر موقع ووقت التحديث وخريطة OpenStreetMap لكل كابتن.
- إدارة حسابات وصلاحيات حسب الدور والمنطقة؛ `*` للأدمن المسؤول عن كل المناطق.

## التحقق

```bash
python3 -m unittest discover -s backend/tests -v
node --check apps/admin/admin.js
cd apps/mobile
npm run typecheck
```

انظر `docs/VALIDATION.md` لنتائج هذه النسخة وحدود الفحوصات. لا تُعد فحوصات الباك إند دليلاً على اختبار أجهزة أندرويد وآيفون.

## ما بقي قبل تشغيل تجاري

التفاصيل في `docs/STATUS.md`: استضافة HTTPS، بناء وتجربة أجهزة حقيقية، إشعارات push، تتبع الخلفية، طلب صوتي، مسارات فعلية، صلاحيات تفصيلية، نسخ احتياطي ومراجعة أمنية ومحاسبية. الخادم المرفق للتطوير، وSQLite مناسب للتجربة الأولية؛ اختر خطة نشر وقاعدة مناسبة لحجم التشغيل قبل اعتماد الخدمة.
